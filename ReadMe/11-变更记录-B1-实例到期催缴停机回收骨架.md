## 功能更新

1. 每个 `ServiceInstance` 补齐到期日程：
   - `expire_time`：到期日（已有；空则从绑定 VPS / Edge 回填）
   - `grace_days`：宽限天数（空则用系统参数，默认 3）
   - `suspend_at`：计划停机日（默认 = 到期日）
   - `recycle_at`：计划回收日（默认 = 到期日 + 宽限）
2. 新增幂等日志 `ServiceExpiryAction`：同一实例、同一到期日、同一动作（含催缴 T-N）只执行一次。
3. 定时任务 `python manage.py process_instance_expiry`：
   - 默认：T-7 / T-3 / T-1 催缴 + 到期通知（走现有 IM 通知规则）
   - **默认不停机、不回收**
   - `--dry-run` 只报告，不写库、不通知
   - `--apply-suspend` / `--apply-recycle` 覆盖系统参数，执行暂停电源或释放 IP / 回收
4. 系统参数（计费分类）：
   - `instance_grace_days=3`
   - `instance_reminder_days=7,3,1`
   - `instance_auto_suspend_on_expire=false`
   - `instance_auto_recycle_after_grace=false`
5. 新通知事件 `service_expiry`（催缴 / 已到期 / 停机 / 回收）。邮件与站内信仍走现有通道开关，本步不另建发送器。
6. 部署骨架：systemd oneshot + 每日 09:00 timer（`ispmanager-instance-expiry`）。

## 验证

```bash
cd ISPmanager/backend
python manage.py migrate
python manage.py test service_manager.tests_instance_expiry --keepdb
python manage.py process_instance_expiry --dry-run
```

生产正式催缴（不停机）：

```bash
python manage.py process_instance_expiry
```

确认要自动停机 / 回收时，先打开系统参数，或单次：

```bash
python manage.py process_instance_expiry --apply-suspend
python manage.py process_instance_expiry --apply-recycle
```

管理端「服务实例」列表应能看到计划停机 / 计划回收；「通知 / IM 对接」可新建规则订阅 `服务到期`。

现网若实例与 VPS/Edge 都没有 `expire_time`，引擎会跳过该实例，需在管理端补到期日后才会催缴。
