## 功能更新

1. **节点鉴权**：`PemanagerClient` 使用 `PopPoint.mgmt_token`（`pem_*` Bearer）。有 Token 时允许不配密码；否则仍走 JWT `login()`。统一入口：`from_pop()` / `connect_pop()` / `authenticate()`。
2. **VNC WebSocket**：有账号密码时仍 `login()` 取 JWT；仅 Token 时用 `pem_*`（节点 WS 可能不认长期 Token，控制台可能失败）。
3. **下发观测**：`interpret_node_write()` 解析节点 `ok` / `steps` / `warning` / QoS。`push_pop_to_node` 返回 `rest_ok`、`apply_ok`、`apply_errors`。`apply_ok` 为假时**不清** `config_dirty`，也不再报「已生效」。
4. **工单 IP**：`_allocate_order_ips` 在 POP 配了基址且（Token 或账号密码）时，把已分配 IP `bulk-create` + `allocate` 到节点。节点失败则抛错，自动开通回滚本地分配并转人工。无 API 配置则跳过（现有无节点用例仍过）。
5. **管理端**：`useConfirmPush` 在 `apply_ok === false` 时警告「节点已收到配置，但系统未确认生效」。门户下发同样看 `apply_ok`。

未做：门户默认改 `dry_run=true`、防火墙中心化、真 PVE 重装/快照、JWT refresh。

## 节点必须打开的写入开关

生产 env 模板默认全关。要对齐中心下发，对应 POP 至少打开：

| 能力 | 环境变量 |
|------|----------|
| GRE / VXLAN / 普通接口 netplan | `INTERFACEMANAGE_NETPLAN_WRITE_ENABLED=1` |
| WireGuard 落地 | `INTERFACEMANAGE_WG_APPLY_ENABLED=1` |
| 静态路由 netplan | `ROUTEMANAGE_NETPLAN_WRITE_ENABLED=1` |
| WG 路由 / `ip route` | `ROUTEMANAGE_IPROUTE_WRITE_ENABLED=1` |
| 策略路由 | `ROUTEMANAGE_IPRULE_WRITE_ENABLED=1` |
| 边缘 QoS（tc） | `QOSMANAGE_APPLY_ENABLED=1` |

PVE 电源 / 创建 / VM 带宽不走上述开关，走节点 proxmoxer。
