# 变更记录 — 全站统一操作日志（log_manager）

**阶段**：运营闭环  
**日期**：2026-08-25  
**范围**：`ISPmanager` 管理端 + 后端  
**前置**：各模块已有分册操作日志，无统一中心页

---

## 功能更新

1. **统一审计表 `AuditLog`**：一条记录包含模块、操作类型、时间、人员、对象、内容、详情 JSON、来源 IP、请求路径。
2. **分模块查看**：管理端「系统设置 → 操作日志」按账号 / 客户 / 账单 / 资源 / 服务 / 产品 / 供应商 / 运维 / 系统 / 门户筛选，并支持类型、人员、关键词、时间范围。
3. **自动汇聚**：资源 / 服务 / 客户（账单收款归入账单模块）/ 产品发布 / 监控同步 / 供应商同步 / IM 发送日志经信号写入统一表；`(source, source_ref)` 幂等，不重复。
4. **写接口补记**：未走专用 `record_*` 的 POST / PUT / PATCH / DELETE（2xx）由中间件补记；已汇聚的请求不双记。密码、Token、密钥写入前脱敏。
5. **认证审计**：登录成功、登录失败、修改密码单独记账，不保存口令。
6. **权限**：新增页面权限 `system.log.view` / `system.log.manage`。超管 / 管理员 / 只读通过 `system.view` 展开获得；客户门户账号不可访问。
7. **历史回填**：`python manage.py sync_audit_logs` 回填分模块历史日志并增量同步权限目录。

不记录：GET / HEAD / OPTIONS、刷新 Token、文档、`/api/log/` 自身、节点高频上报（telemetry / edge-quality ingest）。

---

## 部署要点

1. 应用迁移 `log_manager.0001_initial_auditlog`。
2. 执行 `python manage.py sync_audit_logs`（回填 + 同步「操作日志」页权限）。
3. 更新管理端前端（含 `/system/logs`）。
4. 重启 gunicorn。已登录用户如看不到菜单，重新登录以刷新权限列表。

已有环境可用本目录对应的增量更新包（见 `deploy/` 下 `ispmanager-update-auditlog-*.tar.gz`）或完整发布包 `ispmanager-release-*.tar.gz`。

完整发布包的 `install.sh` 会在安装前检查系统与项目：若已有部署，则备份配置/数据库、按机器调优并走升级路径（不重置密钥与管理员密码）。

## 接口

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | `/api/log/audit-logs/` | `system.log.view` + 系统账号 | 列表；筛选 `module` / `action_type` / `operator_name` / `search` / `created_at_after` / `created_at_before` |
| GET | `/api/log/audit-logs/{id}/` | 同上 | 详情 |
| GET | `/api/log/audit-logs/meta/` | 同上 | 模块、类型、来源及条数 |
