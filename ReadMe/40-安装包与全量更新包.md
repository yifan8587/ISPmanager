# 安装部署包与全量更新包

**日期**：2026-10-04（当前发布 **2.0.0**；1.1.7 说明见 [49-生产发布-1.1.7-安装与在线升级.md](./49-生产发布-1.1.7-安装与在线升级.md)）  

**范围**：`ISPmanager` + `ISPweb` 发布打包与已装系统更新

---

## 一次构建，两套产物

在构建机（需 Node）执行：

```bash
cd /opt/app/ISPmanager/deploy/scripts   # 或仓库内对应路径
bash package.sh
```

| 产物 | 用途 |
|------|------|
| `ispmanager-install-<版本>-<时间戳>.tar.gz` | 新机器一键安装 |
| `ispmanager-update-<版本>-<时间戳>.tar.gz` | 已装系统全量更新，**不影响业务数据** |
| `ispmanager-install-latest.tar.gz` / `ispmanager-update-latest.tar.gz` | 稳定文件名，便于 scp |
| `ispmanager-release-latest.tar.gz` | 兼容旧文档，内容与安装包相同 |

目标机无需 Node。包内不含 `deploy/.env`、`venv`、`backend/media`、`staticfiles`。

---

## 新装

```bash
sudo mkdir -p /opt/app
sudo tar -xzf ispmanager-install-*.tar.gz -C /opt/app --strip-components=1
cd /opt/app
sudo SITE_DOMAIN=www.example.net CERTBOT_EMAIL=ops@example.net bash install.sh
```

说明见包内 `INSTALL.md`。

---

## 全量更新（推荐）

```bash
sudo mkdir -p /tmp/isp-update
sudo tar -xzf ispmanager-update-*.tar.gz -C /tmp/isp-update --strip-components=1
sudo bash /tmp/isp-update/update.sh --root /opt/app
```

脚本会：

1. 确认目标目录是已装系统（存在 `deploy/.env` 或 `venv`），拒绝当新装用
2. 备份 `.env`、`/etc/ispmanager.env`、nginx、可选 `mysqldump`
3. 用 rsync 覆盖后端、部署脚本、两端 `dist`；**排除** `.env` / `media` / `venv`
4. `pip install --upgrade` → `migrate --skip-checks` → `collectstatic`
5. 同步权限/操作日志，重载 nginx 并重启后端

也可在管理端「系统维护」上传更新包（需版本号高于当前）。  
**2.0.0** 起安装脚本会对齐程序目录属主并写入网页升级 sudoers，后续版本可直接走管理端上传更新。说明见 [50-生产发布-2.0.0-安装与在线升级.md](./50-生产发布-2.0.0-安装与在线升级.md)。

## 与旧流程的区别

此前只有一种 `ispmanager-release-*.tar.gz`，已装系统靠「覆盖解压 + `install.sh` 自动探测升级」。  
现改为独立更新包 + `update.sh`：

- 不会走建库、不会生成新密钥、不会写 `/root/ispmanager-credentials.txt`
- 不会因 `--delete` 整棵 `ISPmanager` 而误删源码树里的 `frontend/src`
- 更新包内没有 `install.sh`，降低误跑全新安装的概率

源码树本机更新仍可用：`sudo bash manage-service.sh update`。
