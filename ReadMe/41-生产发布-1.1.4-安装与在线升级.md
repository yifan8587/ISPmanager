## 二、本次程序变更（相对 1.1.3）

### 1. 通知规则 IM 能真正发出

通道「测试发送」成功、规则手动/程序触发不发的问题已修：

- 手动触发按当前规则下发，不再被动作筛选误杀
- 收款动作 `succeeded` 与规则筛选项 `payment` 互通
- 未发出时提示具体原因（未绑通道、事件不匹配、重复抑制、全局开关关闭）

### 2. 基础数据增加可用区

层次：**大区 → 国家 → 城市 → 可用区（可选）**。

- 系统设置 → 基础数据库设置 →「可用区」维护
- POP 可绑定所属城市下的可用区，默认可空
- 资源管理、产品列表可按可用区筛选和展示

升级后会执行迁移 `resource_manager.0027_availability_zone`。

### 3. 默认结算币种与汇率

- 账单设置里结算币种改为单选
- 汇率按所选币种展示为「1 XXX = ? 当前结算币种」
- 出账、钱包、渠道财务汇总按该币种折算统计

升级后请到「系统设置 → 账单设置」确认结算币种和汇率后再保存。

### 4. 节点从备份/模板创建 VPS

ISPmanager「VPS 管理 → 节点创建虚机」与 vpopmanager 使用同一备份时失败的问题已修：

- 按模板记录的真实 PVE 节点（如 `s79157`）查找 `local:backup/...`，不再误用主机别名
- 模板若填写了下载地址，文件缺失时可自动拉取
- 从备份恢复时优先使用可放镜像的磁盘存储（如 `local-lvm`）

## 三、新机器安装

```bash
sha256sum -c ispmanager-install-1.1.4-20260826-170127.tar.gz.sha256

sudo mkdir -p /opt/app
sudo tar -xzf ispmanager-install-1.1.4-20260826-170127.tar.gz -C /opt/app --strip-components=1
cd /opt/app

sudo SITE_DOMAIN=www.example.net \
     CERTBOT_EMAIL=ops@example.net \
     bash install.sh
```

| `SSL_MODE` | 行为 |
|------------|------|
| `auto`（默认） | 域名 A 记录已指向本机则 Let's Encrypt，否则自签 |
| `letsencrypt` | 强制公网证书（80 必须对公网开放） |
| `selfsigned` | 自签，立即 HTTPS（浏览器会告警） |
| `skip` | 仅 HTTP |

首次超级管理员与数据库密码写入 `/root/ispmanager-credentials.txt`（权限 600）。

访问：

- 客户门户：`https://站点域名/`
- 管理端：`https://站点域名/manager`
- Django Admin：`https://站点域名/admin/`
- API：`https://站点域名/api/`

DNS 后补证书：

```bash
sudo SSL_MODE=letsencrypt bash /opt/app/ISPmanager/deploy/scripts/setup-ssl.sh
```

## 四、已装生产环境在线升级（推荐）

**不要**用安装包覆盖正在跑的 `/opt/app`，也不要解压更新包直接盖住 `deploy/.env`。

```bash
sha256sum -c ispmanager-update-1.1.4-20260826-170127.tar.gz.sha256

sudo mkdir -p /tmp/isp-update
sudo tar -xzf ispmanager-update-1.1.4-20260826-170127.tar.gz -C /tmp/isp-update --strip-components=1
sudo bash /tmp/isp-update/update.sh --root /opt/app
```

或：

```bash
sudo bash /opt/app/ISPmanager/deploy/scripts/manage-service.sh update-package \
  --payload /tmp/isp-update --root /opt/app
```

也可在管理端「系统维护」上传 `ispmanager-update-1.1.4-20260826-170127.tar.gz`（版本须高于当前）。

`update.sh` 会：

1. 确认目标是已装系统（存在 `deploy/.env` 或 `venv`）
2. 备份 `.env`、nginx、可选 `mysqldump` 到 `/var/backups/ispmanager/<时间戳>/`
3. 覆盖后端、两端 `dist`、部署脚本；**保留** `.env`、密钥、MySQL 数据、证书、`media`
4. `pip install --upgrade` → `migrate --skip-checks` → `collectstatic`
5. 重载 nginx 并重启后端

迁移失败会中止，不会强行重启成「程序新、库旧」。

源码树本机更新仍可用：`sudo bash /opt/app/ISPmanager/deploy/scripts/manage-service.sh update`。

## 五、升级后检查

1. `systemctl status ispmanager` 为 active
2. 打开管理端 `/manager`、门户 `/`，硬刷新一次（Ctrl+F5）
3. 「通知管理」：通道测试 + 规则手动触发，确认 IM 能发出
4. 「基础数据库设置」出现「可用区」页签；POP / 产品可筛选可用区
5. 「账单设置」结算币种为单选，汇率随币种切换；渠道财务有结算币种汇总
6. 「VPS 管理 → 节点创建虚机」选备份模板后，PVE 节点应是模板上的真实节点名（如 `s79157`）
7. 如 Django Admin 无样式或登录 CSRF 403：

```bash
sudo bash /opt/app/ISPmanager/deploy/scripts/fix-admin-static-csrf.sh
```

## 六、回滚

备份目录：`/var/backups/ispmanager/<时间戳>/`。

1. 停服务：`sudo systemctl stop ispmanager`
2. 按备份恢复程序目录与 `.env`（不要覆盖更新后才写入的业务数据，除非连库一并回滚）
3. 若做了 `mysqldump`，按当时库备份还原
4. `sudo systemctl start ispmanager`

数据库已执行 `0027_availability_zone` 后，回滚程序前需确认旧版本能否兼容该表；不能则连库一起回滚。
