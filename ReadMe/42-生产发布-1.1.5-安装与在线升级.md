## 二、本次程序变更（相对 1.1.4）

### 1. 系统模版目录（核心）

系统设置新增独立功能节点 **「系统模版」**（`/system/os-templates`）。

每条记录包含：系统名称、版本、备份文件名、下载地址（`http://....zst`），以及系统类型、文件类型、启用与排序。

- 产品管理中 VPS「系统版本」与门户下单/重装下拉**读同一张表**，不再写死 Ubuntu / Debian 列表
- 产品可多选允许的系统版本；不选则门户展示全部已启用模版
- 工单「期望操作系统」改为同一套下拉
- 保存模版时同步门户重装用的 `OsImage`

升级后会执行：

- `system_manager.0023_system_os_template`
- `product_manager.0008_product_os_templates`
- `service_manager.0021_os_template_catalog`

自定义角色需在权限管理中勾选「系统模版」查看/管理。

### 2. 采购后自动下发到 POP / PVE

客户门户采购并支付成功后，自动开通会把所选系统版本下发到工单对应 POP：

1. 在该 POP 模板库按文件名 / URL / 名称查找
2. **若不存在**，由 POP 请求中心目录中的 URL，下载到 PVE 并入库
3. 用该模版创建虚机；异步任务会等待完成
4. 回写 VPS 的系统类型与版本

节点需能访问模版下载地址。下载可能耗时，工单会处于「开通中」。

### 3. 产品网络属性与信誉值支付

- IP 块增加网络类型、ASN/企业性质；产品展示从该 POP 下 IP 块聚合
- 门户可用信誉余额或在线支付；信誉支付成功后同样走自动履约
- 升级后会执行 `resource_manager.0028_ipblock_network_type_asn_nature`、`customer_manager.0019_fill_reputation_balance_from_quota`

### 4. 产品节点、支付与开通闭环

- 工单从产品补全期望 POP 与空规格，避免选了产品却开到空节点
- 在线支付回跳 / 轮询成功后幂等履约
- 人工交付支持按产品节点快速建档

### 5. 超管删除未交付工单

- 未交付且无实例的工单可删除；已有实例则拒绝
- 库内外键与模型对齐（账单 / 日志 / 预占），删除不再因 `NO ACTION` 报 500
- 列表未刷新时重复删除已不存在的工单返回 204（幂等）
- 升级后会执行 `service_manager.0020_align_service_order_fk_on_delete`

## 三、新机器安装

```bash
sha256sum -c ispmanager-install-1.1.5-20260830-103417.tar.gz.sha256

sudo mkdir -p /opt/app
sudo tar -xzf ispmanager-install-1.1.5-20260830-103417.tar.gz -C /opt/app --strip-components=1
cd /opt/app

sudo SITE_DOMAIN=www.example.net \
     CERTBOT_EMAIL=ops@example.net \
     bash install.sh
```

| `SSL_MODE` | 行为 |
|------------|------|
| `auto`（默认） | 域名 A 记录已指向本机则 Let's Encrypt，否则自签 |
| `letsencrypt` | 强制公网证书（80 必须对公网开放） |
| `selfsigned` | 自签，立即 HTTPS（浏览器会告警） |
| `skip` | 仅 HTTP |

首次超级管理员与数据库密码写入 `/root/ispmanager-credentials.txt`（权限 600）。

访问：

- 客户门户：`https://站点域名/`
- 管理端：`https://站点域名/manager`
- Django Admin：`https://站点域名/admin/`
- API：`https://站点域名/api/`

DNS 后补证书：

```bash
sudo SSL_MODE=letsencrypt bash /opt/app/ISPmanager/deploy/scripts/setup-ssl.sh
```

新装后请到「系统设置 → 系统模版」录入名称、版本、备份文件名和可访问的 `.zst` URL，再在产品中勾选可选系统版本。

## 四、已装生产环境在线升级（推荐）

**不要**用安装包覆盖正在跑的 `/opt/app`，也不要解压更新包直接盖住 `deploy/.env`。

```bash
sha256sum -c ispmanager-update-1.1.5-20260830-103417.tar.gz.sha256

sudo mkdir -p /tmp/isp-update
sudo tar -xzf ispmanager-update-1.1.5-20260830-103417.tar.gz -C /tmp/isp-update --strip-components=1
sudo bash /tmp/isp-update/update.sh --root /opt/app
```

或：

```bash
sudo bash /opt/app/ISPmanager/deploy/scripts/manage-service.sh update-package \
  --payload /tmp/isp-update --root /opt/app
```

也可在管理端「系统维护」上传 `ispmanager-update-1.1.5-20260830-103417.tar.gz`（版本须高于当前 `1.1.4`）。

`update.sh` 会：

1. 确认目标是已装系统（存在 `deploy/.env` 或 `venv`）
2. 备份 `.env`、nginx、可选 `mysqldump` 到 `/var/backups/ispmanager/<时间戳>/`
3. 覆盖后端、两端 `dist`、部署脚本；**保留** `.env`、密钥、MySQL 数据、证书、`media`
4. `pip install --upgrade` → `migrate --skip-checks` → `collectstatic`（含权限同步）
5. 重载 nginx 并重启后端

迁移失败会中止，不会强行重启成「程序新、库旧」。

源码树本机更新仍可用：`sudo bash /opt/app/ISPmanager/deploy/scripts/manage-service.sh update`。

## 五、升级后检查

1. `systemctl status ispmanager` 为 active；侧栏版本显示 **V1.1.5**
2. 打开管理端 `/manager`、门户 `/`，硬刷新一次（Ctrl+F5）
3. 「系统设置 → 系统模版」可新增记录；产品编辑出现「系统版本」多选
4. 门户 VPS 下单操作系统下拉来自库中模版，不再是写死列表
5. 产品页网络类型 / ASN 与 POP 下 IP 块一致；信誉支付入口按产品与客户开通情况显示
6. 未交付且无实例的工单，超管可删除
7. 如 Django Admin 无样式或登录 CSRF 403：

```bash
sudo bash /opt/app/ISPmanager/deploy/scripts/fix-admin-static-csrf.sh
```

## 六、回滚

备份目录：`/var/backups/ispmanager/<时间戳>/`。

1. 停服务：`sudo systemctl stop ispmanager`
2. 按备份恢复程序目录与 `.env`（不要覆盖更新后才写入的业务数据，除非连库一并回滚）
3. 若做了 `mysqldump`，按当时库备份还原
4. `sudo systemctl start ispmanager`

本版已执行系统模版、产品 M2M、工单外键等迁移后，回滚程序前需确认旧版本能否兼容新表；不能则连库一起回滚。
