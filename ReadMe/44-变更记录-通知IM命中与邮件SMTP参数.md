# 变更记录 — 通知 IM 命中修复与邮件 SMTP 参数

**日期**：2026-08-31  
**对应**：系统设置 → 通知/IM 对接；参数配置 → 对内通知

---

## 问题

1. 已配置 IM 通道和通知规则，但资源变更、门户操作没有推到 IM。
2. 参数里只有客服邮箱，邮件服务器地址/端口无法在界面配置，实际发信依赖环境变量。

## 原因

- 资源审计按对象拆成 `vps_change` / `edge_acceleration_change` / `ip_change` 等。只订阅「资源异动」时，这些细分事件对不上规则。
- 门户下单、直付确认、变更申请未映射到稳定动作码，会被「仅创建工单」一类动作筛选滤掉。
- SMTP 只读 `DJANGO_EMAIL_*`，界面无法配主机和端口。

## 功能更新

1. **资源异动覆盖细分事件**：规则勾选「资源异动」即命中 VPS / 边缘加速 / POP / IP / 带宽。父事件上的动作筛选对子事件同样生效。
2. **门户动作码**：下单 / 直付确认 → `create_order`；变更申请 → `change`；续费 → `renew`。
3. **门户写操作**：协议配置、下发、电源等在写资源日志后，若已绑定服务实例，再补发一条「服务变更」，便于只订阅服务变更的规则也能收到。
4. **邮件 SMTP 参数**：`smtp_host` / `smtp_port` / `smtp_user` / `smtp_password` / `smtp_use_ssl` / `smtp_use_tls`。密码不回显，留空保存不改原值。填写主机后优先于环境变量。
5. 未投递时在服务日志记下跳过原因，便于排查「有规则却没发出去」。

## 运营配置

1. 「系统设置 → 对内通知」打开「启用 IM 通知」，规则绑定已启用通道。建议至少勾选「资源异动」「服务工单」。
2. 填写客服邮箱、邮件服务器、端口、账号；打开「启用邮件通知」后业务事件才会自动发信。测试邮件不要求先开总开关。
3. 部署后执行迁移 `system_manager.0024_smtp_settings`，以写入新增参数项。
