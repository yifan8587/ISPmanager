## 二、本次程序变更（相对 1.1.5）

### 1. VPS 改为发行版 Cloud 镜像开通（核心）

QEMU 虚机不再用 `vzdump` / `.vma.zst` 恢复，改为各发行版官方 Cloud 版 `.qcow2` / `.img`：

1. 空壳 VM（`virtio-scsi-single` / `ostype=l26`）
2. `scsi0` `import-from` Cloud 镜像并扩盘
3. 引导、串口控制台、qemu-guest-agent
4. 挂 `ide2` cloud-init，写入用户 / 密码 / IP / DNS

`.vma.zst` 开通直接拒绝。LXC `vztmpl`、已转成 PVE 模板虚机的克隆仍可用。

中心「系统模版」默认类型为 **Cloud 镜像**。可：

- 「导入官方 Cloud 目录」（Ubuntu / Debian / AlmaLinux / Rocky）
- 「从 POP 同步」节点模板库；已配好的 Cloud URL 不覆盖；同名 `.vma.zst` 备份会就地升级为 Cloud
- 产品勾选可用系统版本；门户下单 / 重装只展示**可 Cloud 开通**的条目（待升级备份对客户隐藏）

POP 缺失该镜像时，按中心填写的官方 URL 下载到 PVE `iso` 存储（`/var/lib/vz/template/iso/`），再创建或重装。

升级后会执行 `system_manager.0025_os_template_cloud_source`。

### 2. 开通 / 重装写入密码与 IP（cloud-init）

- 自动开通生成随机管理密码，并按系统推断 cloud-init 用户（如 `ubuntu` / `debian` / `almalinux`）
- 产品含 IP 数量时：从该 POP 空闲地址分配；池不足则从已有地址块生成，再把 **地址 / CIDR / 网关** 写入 cloud-init
- 无 IP 产品不传空 `ip` / `gateway` / `prefix`，走 DHCP，避免节点接口 400
- 门户重装会先确保 POP 上有 Cloud 镜像，并把已分配 IP 一并下发
- 门户改密仍走节点 Guest Agent

### 3. IP 录入网关 / 掩码与 NAT 交付

- 地址列表支持单个、不连续、起止、CIDR；可填本段掩码与网关
- 地址块新增「本段网关」，解析 IP 时写入新地址
- POP 增加「IP 交付方式」：公网直连 / NAT；产品与门户在 NAT 时提示

升级后会执行 `resource_manager.0030_ip_gateway_and_nat_delivery`、`resource_manager.0031_alter_greconfig_local_ip`。

### 4. 边缘加速：先预分配，客户补全后再下发

付款成功后只预占带宽、业务 IP、隧道地址段，实例处于「开通中」。  
客户在门户「协议配置」补全对端后「保存并下发」，节点生效再激活。  
升级后会执行 `resource_manager.0029_greconfig_remote_ip_nullable`。

### 5. 通知 IM 命中与邮件 SMTP 参数

- 「资源异动」覆盖 VPS / 边缘 / POP / IP / 带宽细分事件
- 门户下单、直付、变更、续费有稳定动作码，规则能真正命中
- 参数配置可填 SMTP 主机 / 端口 / 账号；密码不回显

升级后会执行 `system_manager.0024_smtp_settings`。

## 三、新机器安装

```bash
sha256sum -c ispmanager-install-1.1.6-20260906-151944.tar.gz.sha256

sudo mkdir -p /opt/app
sudo tar -xzf ispmanager-install-1.1.6-20260906-151944.tar.gz -C /opt/app --strip-components=1
cd /opt/app

sudo SITE_DOMAIN=www.example.net \
     CERTBOT_EMAIL=ops@example.net \
     bash install.sh
```

| `SSL_MODE` | 行为 |
|------------|------|
| `auto`（默认） | 域名 A 记录已指向本机则 Let's Encrypt，否则自签 |
| `letsencrypt` | 强制公网证书（80 必须对公网开放） |
| `selfsigned` | 自签，立即 HTTPS（浏览器会告警） |
| `skip` | 仅 HTTP |

首次超级管理员与数据库密码写入 `/root/ispmanager-credentials.txt`（权限 600）。

访问：

- 客户门户：`https://站点域名/`
- 管理端：`https://站点域名/manager`
- Django Admin：`https://站点域名/admin/`
- API：`https://站点域名/api/`

DNS 后补证书：

```bash
sudo SSL_MODE=letsencrypt bash /opt/app/ISPmanager/deploy/scripts/setup-ssl.sh
```

新装后请到「系统设置 → 系统模版」点「导入官方 Cloud 目录」，再在产品中勾选可选系统版本。  
节点须已升级 vpopmanager 1.1.0+，并能访问镜像下载地址。

## 四、已装生产环境在线升级（推荐）

**不要**用安装包覆盖正在跑的 `/opt/app`，也不要解压更新包直接盖住 `deploy/.env`。

```bash
sha256sum -c ispmanager-update-1.1.6-20260906-151944.tar.gz.sha256

sudo mkdir -p /tmp/isp-update
sudo tar -xzf ispmanager-update-1.1.6-20260906-151944.tar.gz -C /tmp/isp-update --strip-components=1
sudo bash /tmp/isp-update/update.sh --root /opt/app
```

或：

```bash
sudo bash /opt/app/ISPmanager/deploy/scripts/manage-service.sh update-package \
  --payload /tmp/isp-update --root /opt/app
```

也可在管理端「系统维护」上传 `ispmanager-update-1.1.6-20260906-151944.tar.gz`（版本须高于当前 `1.1.5`）。

`update.sh` 会：

1. 确认目标是已装系统（存在 `deploy/.env` 或 `venv`）
2. 备份 `.env`、nginx、可选 `mysqldump` 到 `/var/backups/ispmanager/<时间戳>/`
3. 覆盖后端、两端 `dist`、部署脚本；**保留** `.env`、密钥、MySQL 数据、证书、`media`
4. `pip install --upgrade` → `migrate --skip-checks` → `collectstatic`
5. 重载 nginx 并重启后端

迁移失败会中止，不会强行重启成「程序新、库旧」。

源码树本机更新仍可用：`sudo bash /opt/app/ISPmanager/deploy/scripts/manage-service.sh update`。

## 五、升级后检查

1. `systemctl status ispmanager` 为 active；侧栏版本显示 **V1.1.6**
2. 打开管理端 `/manager`、门户 `/`，硬刷新一次（Ctrl+F5）
3. 「系统设置 → 系统模版」可导入官方 Cloud 目录 / 从 POP 同步；旧 `.vma.zst` 显示「待升级备份」
4. 产品「系统版本」勾选后，门户下单只出现可 Cloud 开通的条目
5. 开通带 IP 的产品：工单完成后 VPS 有管理密码，cloud-init 含地址 / CIDR / 网关
6. 门户「重装系统」可选 Cloud 镜像，已分配 IP 会一并下发
7. NAT 节点在产品 / 门户有交付提示；地址块可填本段网关
8. 边缘加速付款后为「待配置」，客户补全协议后再下发
9. 「对内通知」规则勾选「资源异动」后，VPS / IP 变更能推到 IM；SMTP 参数可在界面填写
10. 如 Django Admin 无样式或登录 CSRF 403：

```bash
sudo bash /opt/app/ISPmanager/deploy/scripts/fix-admin-static-csrf.sh
```

11. 若升级日志出现 `Permission denied: '.../ReadMe/....md'`：不要用安装包做在线升级。先修属主或改走 CLI（见 `ReadMe/48-变更记录-在线升级ReadMe权限拒绝.md`），再上传 `ispmanager-update-*.tar.gz`。

## 六、回滚

备份目录：`/var/backups/ispmanager/<时间戳>/`。

1. 停服务：`sudo systemctl stop ispmanager`
2. 按备份恢复程序目录与 `.env`（不要覆盖更新后才写入的业务数据，除非连库一并回滚）
3. 若做了 `mysqldump`，按当时库备份还原
4. `sudo systemctl start ispmanager`

本版已执行 Cloud 模版、SMTP、IP 网关 / NAT、GRE 对端可空等迁移后，回滚程序前需确认旧版本能否兼容新表；不能则连库一起回滚。
