# 生产发布 2.0.0：Ubuntu 22.04 完整安装与网页在线升级

**日期**：2026-10-04  
**版本**：`2.0.0`（SSL / 内网 NAT 请改用 **2.0.1** 包，见 [51-内网NAT发布与SSL.md](./51-内网NAT发布与SSL.md)）  
**范围**：`ISPmanager` 管理端 + Django 后端，`ISPweb` 客户门户

本说明对应本次打出的两套压缩包，面向 **Ubuntu 22.04 LTS**（兼容 24.04）。  
继续沿用 1.1.x 的单域名路径分流、Django Admin 完整加载与 CSRF 修复；并在安装时对齐权限，使**后续新版本可在管理端网页自动升级**。

## 二、URL 分流（与 1.1.x 一致）

同一 `SITE_DOMAIN`，由 nginx 按路径区分前后端，**不要**把 API 挂到 `/manager` 下：

| 入口 | 路径 | 后端 |
|------|------|------|
| 客户门户（ISPweb） | `/` | 静态 `ISPweb/dist` |
| 管理端 SPA | `/manager/` | 静态 `ISPmanager/frontend/dist`（生产 `vite base=/manager/`） |
| Django Admin | `/admin/` | gunicorn，`STATIC_URL=/static/` |
| REST / OpenAPI | `/api/` | gunicorn |
| WebSocket | `/ws/` | gunicorn + uvicorn worker |
| 静态 / 上传 | `/static/` `/media/` | collectstatic / media |

两端前端均请求同源 `/api`、`/ws`，无跨域。  
支付回跳地址必须是 `https://站点/manager`，不能只写站点根。

## 三、本次相对 1.1.7 的变化

### 1. 客户门户 2.0

- 首页直接进入商品选购（京东式目录），原介绍文案迁到页脚「产品介绍 / 使用帮助」
- 品牌由 CloudEdge 调整为 **10g.hk**，全站使用透明底 LOGO
- 商品展示：公网对接分类、月租、IP 属性；下单时选择 GRE / WG

### 2. 部署权限：支持后续网页自动更新

安装与 CLI 更新结束后会执行 `prepare_web_upgrade_permissions`：

1. 把 `backend`、`frontend`、`ISPweb`、`ReadMe`、`deploy`、`venv`、`staticfiles`、`media` 交给服务用户 `ispmanager`
2. 目录加 **setgid + 组可写**，下次覆盖的新文件仍可被 gunicorn 写入
3. `deploy/.env` 保持 `root:ispmanager` `640`
4. 写入 `/etc/sudoers.d/ispmanager-web-upgrade`，允许 `ispmanager` 无密码执行：
   - `systemctl restart ispmanager.service`
   - `systemctl restart ispmanager-pop-quality.service`
   - `systemctl reload nginx`
5. 运行时环境写入  
   `SYSTEM_UPGRADE_RESTART_CMD=sudo -n /bin/systemctl restart ispmanager.service`

因此 2.0.0 装好后，**以后的 `ispmanager-update-*.tar.gz` 可直接在管理端「系统维护」上传**，覆盖程序、迁移数据库、收集静态并自动重启。

一次性补齐已装环境：

```bash
sudo bash /opt/app/ISPmanager/deploy/scripts/prepare-web-upgrade.sh --root /opt/app
```

### 3. Django Admin 与 CSRF（沿用并纳入自检）

- 生产强制 `SECURE_PROXY_SSL_HEADER` + `USE_X_FORWARDED_HOST/PORT`
- 按 `SITE_DOMAIN` / 别名 / `ALLOWED_HOSTS` / 映射端口展开 `CSRF_TRUSTED_ORIGINS`
- nginx 反代使用 `$http_host` 与 `X-Forwarded-Proto`
- 安装 / 升级强制 `collectstatic`，保证 `/static/admin/css/base.css`
- `verify-install.sh` 会探测 Admin 登录页 CSRF token 与 Admin CSS

登录仍 403 或无样式时：

```bash
sudo bash /opt/app/ISPmanager/deploy/scripts/fix-admin-static-csrf.sh
```

## 四、新机器安装（Ubuntu 22.04）

```bash
sha256sum -c ispmanager-install-2.0.0-20261004-141343.tar.gz.sha256

sudo mkdir -p /opt/app
sudo tar -xzf ispmanager-install-2.0.0-20261004-141343.tar.gz \
  -C /opt/app --strip-components=1
cd /opt/app

sudo SITE_DOMAIN=www.example.net \
     CERTBOT_EMAIL=ops@example.net \
     bash install.sh
```

`install.sh` 依次：生成密钥与 `.env` → 系统依赖（Python 3.12 / nginx / MySQL / certbot）→ 建库 → 后端依赖 + collectstatic → systemd + nginx → HTTPS → **网页升级权限** → 自检。

| `SSL_MODE` | 行为 |
|------------|------|
| `auto`（默认） | 域名 A 记录已指向本机则 Let's Encrypt，否则自签 |
| `letsencrypt` | 强制公网证书（80 必须对公网开放） |
| `selfsigned` | 自签，立即 HTTPS（浏览器会告警） |
| `skip` | 仅 HTTP |

首次超级管理员与数据库密码写入 `/root/ispmanager-credentials.txt`（权限 600）。

访问：

- 客户门户：`https://站点域名/`
- 管理端：`https://站点域名/manager`
- Django Admin：`https://站点域名/admin/`
- API / 文档：`https://站点域名/api/` 、`/api/docs/`

DNS 后补证书：

```bash
sudo SSL_MODE=letsencrypt bash /opt/app/ISPmanager/deploy/scripts/setup-ssl.sh
```

源码树分步安装（开发机，需 Node）：

```bash
cd /opt/app/ISPmanager/deploy
cp .env.example .env
cd scripts
sudo bash 01-init-ubuntu.sh
sudo bash 02-setup-database.sh
bash build.sh
sudo bash deploy.sh
sudo bash setup-ssl.sh
sudo bash verify-install.sh
```

## 五、已装生产环境升级到 2.0.0

**不要**用安装包覆盖正在跑的 `/opt/app`，也不要解压更新包直接盖住 `deploy/.env`。

```bash
sha256sum -c ispmanager-update-2.0.0-20261004-141343.tar.gz.sha256

sudo mkdir -p /tmp/isp-update
sudo tar -xzf ispmanager-update-2.0.0-20261004-141343.tar.gz \
  -C /tmp/isp-update --strip-components=1
sudo bash /tmp/isp-update/update.sh --root /opt/app
```

或：

```bash
sudo bash /opt/app/ISPmanager/deploy/scripts/manage-service.sh update-package \
  --payload /tmp/isp-update --root /opt/app
```

从 **1.1.7 及更早** 第一次升到 2.0.0 时，当前 Web 进程可能仍无权覆盖 `ReadMe` / 前端。**请用上面的 root CLI**。升完 2.0.0 之后，再升 2.0.1+ 即可走网页。

若坚持先修权限再网页升级：

```bash
sudo bash /opt/app/ISPmanager/deploy/scripts/prepare-web-upgrade.sh --root /opt/app
```

然后在管理端「系统维护」上传 **`ispmanager-update-2.0.0-*.tar.gz`**（版本须高于当前）。

`update.sh` 会：

1. 确认目标是已装系统（存在 `deploy/.env` 或 `venv`）
2. 备份 `.env`、nginx、可选 `mysqldump` 到 `/var/backups/ispmanager/<时间戳>/`
3. 覆盖后端、两端 `dist`、部署脚本与文档；**保留** `.env`、密钥、MySQL 数据、证书、`media`
4. `pip install --upgrade` → `migrate --skip-checks` → `collectstatic`
5. 对齐网页升级权限与 sudoers
6. 重载 nginx 并重启后端

迁移失败会中止，不会强行重启成「程序新、库旧」。

## 六、后续新版本的网页更新模式

2.0.0 装好或 CLI 升到 2.0.0 之后：

1. 在构建机执行 `bash ISPmanager/deploy/scripts/package.sh`，得到更高版本的 `ispmanager-update-<版本>-*.tar.gz`
2. 登录管理端 → **系统维护** → 上传该 update 包（须高于当前 `2.0.0`）
3. 系统自动备份 → 覆盖 ISPmanager + ISPweb → `apply.sh`（依赖 / 迁移 / 静态）→ 重启服务
4. 侧栏版本号变为新版本

约束：

- 只上传 **update** 包，不要上传 `ispmanager-install-*.tar.gz`
- 包内必须有语义化 `ISPmanager/VERSION` 或 `manifest.json`，不要用 `deploy/VERSION` 的日期当版本
- 服务用户必须能写程序目录（2.0.0 安装脚本已设置）
- 重启依赖 sudoers；缺失时执行 `prepare-web-upgrade.sh`

源码树本机更新仍可用：`sudo bash /opt/app/ISPmanager/deploy/scripts/manage-service.sh update`。

## 七、升级后检查

1. `systemctl status ispmanager` 为 active；侧栏版本显示 **V2.0.0**
2. 门户 `/` 为商品目录，品牌为 10g.hk，LOGO 无黑色底板
3. 管理端 `/manager/` 硬刷新一次（Ctrl+F5），静态资源路径带 `/manager/`
4. Django Admin `/admin/login/` 有完整样式，登录不再 CSRF 403
5. `/static/admin/css/base.css` 返回 200
6. `/api/docs/` 可打开
7. `ls -l /etc/sudoers.d/ispmanager-web-upgrade` 存在
8. `sudo -u ispmanager test -w /opt/app/ISPmanager/VERSION` 成功
9. 如 Admin 无样式或 CSRF 403：执行 `fix-admin-static-csrf.sh`

## 八、回滚

备份目录：`/var/backups/ispmanager/<时间戳>/`。

1. `sudo systemctl stop ispmanager`
2. 按备份恢复程序目录与 `.env`（不要覆盖更新后才写入的业务数据，除非连库一并回滚）
3. 若做了 `mysqldump`，按当时库备份还原
4. `sudo systemctl start ispmanager`
